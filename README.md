# synthetic-data-generator

A small library for generating synthetic tabular data and, more importantly,
for saying honestly how good the generated data is. Most "synthetic data" demos
show a sample and stop; the interesting question is whether the copy keeps the
per-column distributions, the correlations between columns, and the rare
categories — and whether it is safe to share. This repo implements two
generators with different failure modes and one evaluation module that scores
both on fidelity and privacy.

The source table is generated by the package itself (`synthdata/source.py`) from
a seed: seven columns with three numeric types (one heavy tailed, one bounded
and discrete), three categorical columns (one of which depends on a numeric
column), and a datetime column. Nothing is downloaded, so a run is reproducible
from the commit alone.

## What is in the box

| Module | Job |
| --- | --- |
| `src/synthdata/profile.py` | Infers each column's kind (numeric / categorical / datetime / constant) and computes the per-column statistics every other module works from. |
| `src/synthdata/source.py` | Builds the mixed-type source table from a seed, with correlated latents, a logistic churn label and a datetime column. Also reads/writes it as CSV. |
| `src/synthdata/copula.py` | Gaussian copula: rank-normalise each numeric column, fit and repair the correlation matrix, sample, inverse-transform. Categorical columns are conditioned on the driver column by quantile bin. |
| `src/synthdata/ctgan.py` | CTGAN-lite in PyTorch (CPU): mode-specific normalisation of continuous columns, one-hot categoricals, conditional vectors, a small generator/discriminator loop. |
| `src/synthdata/evaluate.py` | Fidelity (per-column KS, correlation-matrix delta, categorical total variation) and privacy (distance to closest record, exact and internal duplicate rate). |
| `src/synthdata/config.py` | Typed view of `config.yaml`, with validation that names the offending key. |
| `src/synthdata/cli.py` | `profile`, `generate`, `evaluate`, `run-all`, `config` commands. |
| `tests/` | 79 tests over the five modules above. |

## Quickstart

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# what does the source table look like?
make profile     # PYTHONPATH=src python -m synthdata profile

# generate 2000 rows with the copula and score them
make generate    # PYTHONPATH=src python -m synthdata generate --generator copula --rows 2000
PYTHONPATH=src python -m synthdata evaluate --source artifacts/source.csv --synthetic synthetic.csv

# or run the whole pipeline: profile, both generators, both reports
make run-all

make test        # 79 tests
```

`pip install -e .` also works and puts the `synthdata` console script on the
path, so the `PYTHONPATH` prefix is only needed for a bare checkout.

`run-all` writes `artifacts/source.csv`, `artifacts/synthetic-{copula,ctgan}.csv`
and `artifacts/report-{copula,ctgan}.json`.

## Design notes

**The copula works on ranks, not values.** Fitting a correlation matrix on raw
values lets one heavy-tailed column (income here) decide the whole geometry: two
rows that differ by 10k are "far apart" in a way that has nothing to do with
their rank. Rank-normalising first makes every column standard normal by
construction, so the fitted matrix describes co-occurrence rather than units.
The cost is that the copula cannot represent a dependency that is invisible in
ranks, such as a variance that changes with the mean.

**The correlation matrix is repaired before it is sampled.** A matrix estimated
from a finite sample is not guaranteed to be positive semi-definite, and
factorising it raises or silently produces complex numbers. `repair_correlation`
clips negative eigenvalues to a small floor and re-normalises the diagonal, which
is the smallest change that makes the matrix usable. It is applied on every fit,
not just when a test fails.

**Categorical columns are conditioned, not independent.** Sampling `plan`
independently of `income` produces a table where the marginals look right and
every joint distribution is wrong. The copula bins the first numeric column by
quantile and stores `P(level | bin)` with Laplace smoothing; the CTGAN approach
is the same idea learned instead of tabulated, through the conditional vector.

**Mode-specific normalisation exists because tenure has spikes.** A global
z-score on a column with several modes smears them into a uniform blob, and the
generator can never put mass back on a cluster it cannot see. Each value is
assigned to its nearest mode and normalised inside that mode; the mode index is
part of the conditioning. `ModeSpecificNormalizer.transform` is the exact
algebraic transform — the `[-1, 1]` range is a property of the generator's
`tanh` output and is applied only to training rows.

**Privacy is measured with a copy-detector, not a promise.** `dcr` is the L2
distance from each synthetic row to its nearest real row after min-max scaling.
A generator that memorises scores ~0; a generator that has collapsed scores 0 on
`internal_duplicate_rate` instead. Reporting both is what makes the trade-off
visible.

## Tests

79 tests, run with `python -m pytest -q` (about 9 s on CPU).

- `tests/test_profile.py` (11) — kind inference for all four kinds, discrete
  numbers staying numeric, the high-cardinality rejection path, exact numeric
  statistics, sorted categorical frequencies, datetime precision, missing-rate
  accounting, and the empty-frame errors.
- `tests/test_copula.py` (16) — normal scores really are standard normal, the
  monotone/tie behaviour of rank normalisation, the quantile roundtrip, PSD
  repair on a deliberately broken matrix, empirical correlation of sampled
  latents within 0.03, and sampled columns staying inside the source ranges and
  keeping the strongest real correlation within 0.15.
- `tests/test_ctgan.py` (13) — exact normaliser roundtrip, planted modes
  recovered within 2 units, one-hot roundtrip and unseen-level handling,
  generator/discriminator tensor shapes, sampled columns inside the source
  ranges, one loss per epoch, and byte-identical samples for a fixed seed.
- `tests/test_evaluate.py` (22) — KS is 0 for identical samples and 1 for
  disjoint ones, total variation is 0/1/0.25 on hand-computed distributions,
  correlation delta is exactly 0 for a frame against itself and detects a
  shuffled column, DCR is ~0 for copied rows and larger for perturbed ones, and
  duplicate rates distinguish a copy from a collapsed table.
- `tests/test_cli_config.py` (17) — source determinism and seed sensitivity,
  declared bounds, churn rate and its tenure dependency, CSV roundtrip, config
  loading and its three error paths, CLI exit codes and written artefacts.

## Limitations

- The copula models only linear dependence in rank space. Non-monotone
  relationships (a U-shaped effect, for example) are not recovered.
- Datetime columns are reproduced by resampling their observed values. They are
  not modelled jointly with the numeric columns, so a synthetic row can carry a
  signup date that does not follow from its tenure.
- CTGAN-lite is small on purpose: two hidden layers, one discriminator update
  per generator update, no packing or PacGAN, no mode collapse detector. It
  trains in seconds and is meant to be readable, not to beat a full CTGAN.
- The evaluation compares one synthetic table to one real table. There is no
  confidence interval on any metric, and no train/test split of the real data,
  so a generator that overfits its training rows is only caught by the privacy
  block.
- Missing values are profiled and their rate is compared, but neither generator
  emits missing cells; a column with 20% missing in the source comes back
  complete in the copy.
- No differential-privacy guarantee is offered or claimed. The privacy metrics
  are diagnostics, not a proof.
